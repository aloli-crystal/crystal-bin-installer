English version: link:README.adoc[README.adoc]

Compilation et installation en une commande de tout un écosystème de
shards Crystal d'un dossier local.

`crystal-bin-installer` parcourt un répertoire source, détecte chaque
projet Crystal déclarant une section `targets:` dans son `shard.yml`,
vérifie qu'il est bien synchronisé avec `origin/production`, le compile
et copie le binaire produit dans un répertoire de destination (par
défaut `~/bin`) pour le rendre immédiatement disponible via le `$PATH`
du shell.

== Pourquoi

Quand on entretient une dizaine de shards Crystal, taper
`shards build --release` dans chacun puis copier les binaires à la main
dans `~/bin` est fastidieux. Cet outil le fait en une seule commande,
et refuse d'installer un binaire qui ne refléterait pas ce qui est sur
GitHub.

== Fonctionnalités

* **Auto-découverte** — tout sous-répertoire direct contenant un
  `shard.yml` est inspecté.
* **Détection des binaires** — les projets sans section `targets:`
  (bibliothèques pures) sont silencieusement ignorés.
* **Vérification de synchronisation git** — avant la compilation,
  chaque dépôt doit être sur la branche `production`, avoir un arbre
  de travail propre et être à jour avec `origin/production`.
* **Mode release par défaut** — utilise `shards build --release`.
  Passez `--dev` pour une compilation plus rapide non optimisée.
* **Dry-run** — `--dry-run` affiche ce qui serait fait sans toucher
  au disque.
* **Récapitulatif coloré** — un rapport final liste les projets
  installés, en échec et exclus, avec la raison de chaque échec.

== Installation

[source,shell]
----
git clone git@github.com:aloli-crystal/crystal-bin-installer.git
cd crystal-bin-installer
shards build --release
cp bin/crystal-bin-installer ~/bin/
----

== Utilisation

[source,shell]
----
# Par défaut : parcourt ~/prod-crystal, installe dans ~/bin, mode release, fetch activé.
crystal-bin-installer

# Simulation à partir d'un autre dossier.
crystal-bin-installer --dir ~/work/crystal --dry-run

# Exclure deux projets et compiler en mode dev.
crystal-bin-installer --dev --skip crystal-asciidoctor,crystal-experimental

# Ignorer les vérifications git (compile même les dépôts sales).
crystal-bin-installer --force

# Ne pas récupérer les références distantes (plus rapide mais état potentiellement obsolète).
crystal-bin-installer --no-fetch
----

== Options

[cols="1,3"]
|===
| Option | Description

| `--config CHEMIN`
| Chemin du fichier de configuration utilisateur (par défaut :
  `~/.crystal-bin-installer.yml`).

| `--dir CHEMIN`
| Répertoire source à parcourir (par défaut : `~/prod-crystal`).

| `--dest CHEMIN`
| Répertoire de destination des binaires (par défaut : `~/bin`).

| `--dev`
| Compile en mode développement au lieu de `--release`.

| `--skip NOMS`
| Liste de projets à exclure, séparés par des virgules. Additif avec le
  fichier de configuration (les deux listes sont fusionnées, pas
  remplacées).

| `--dry-run`
| Affiche ce qui serait fait sans rien écrire.

| `--no-fetch`
| N'exécute pas `git fetch` avant la vérification de synchronisation.

| `--force`
| Ignore entièrement les vérifications git.

| `-v`, `--version`
| Affiche la version et quitte.

| `-h`, `--help`
| Affiche l'aide et quitte.
|===

== Fichier de configuration

Un fichier de configuration utilisateur est automatiquement chargé
depuis `~/.crystal-bin-installer.yml` s'il existe, pour éviter de
passer les mêmes options à chaque lancement. Le chemin peut être
surchargé avec `--config CHEMIN`.

Ordre de précédence (du plus faible au plus fort) : **valeurs par
défaut → fichier de configuration → options en ligne de commande**.
`--skip` est la seule option additive : la liste du fichier de
configuration et celle du CLI sont fusionnées.

.Exemple `~/.crystal-bin-installer.yml`
[source,yaml]
----
# Surcharge des valeurs par défaut : répertoire source personnalisé,
# compilation en mode dev, exclusion de projets dont les binaires ne
# doivent pas atterrir dans ~/bin.
dir: ~/prod-crystal
dest: ~/bin
release: true
fetch: true
force: false
skip:
  - crystal-beryl
  - crystal-asciidoctor
  - crystal-silex
  - crystal-load-env
  - crystal-i18n
----

Clés supportées :

[cols="1,3"]
|===
| Clé | Type / description

| `dir` | Chaîne — répertoire source (équivalent de `--dir`).
| `dest` | Chaîne — répertoire de destination (équivalent de `--dest`).
| `release` | Booléen — compiler en mode release (par défaut : `true`).
| `fetch` | Booléen — exécuter `git fetch` avant la vérification (par défaut : `true`).
| `force` | Booléen — ignorer les vérifications git (par défaut : `false`).
| `skip` | Liste de chaînes — projets à exclure.
|===

== Codes de sortie

* `0` — toutes les cibles détectées ont été installées avec succès.
* `1` — au moins une cible a échoué (erreur de compilation, dépôt
  désynchronisé, `shard.yml` invalide, etc.).
